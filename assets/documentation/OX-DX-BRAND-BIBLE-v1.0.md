**Status: CANONICAL**

**Version: v1.0**

This is the master brand reference for the OX-DX ecosystem.

## 4. Brand Personality

OX-DX is:

### INTELLIGENT
Reason through distinctions. Do not decorate intelligence.

### CURIOUS
Observe before deciding.

### PRECISE
Name scope, status, evidence, and uncertainty.

### RAW
Preserve useful traces. Do not polish evidence into false certainty.

### REFLECTIVE
Allow depth and philosophical questions without pretending they are technical proof.

### INDEPENDENT
Do not imitate dominant technology brands merely because a style is fashionable.

### DISCIPLINED
Use canonical terminology, assets, status language, and change control.

### SLIGHTLY MYSTERIOUS
Use controlled negative space and conceptual tension without making technical meaning obscure.

OX-DX is not corporate-by-default, luxury, cute, playful SaaS, aggressive, religious authority, or futuristic for its own sake.

## 6. Brand Story

Reality does not arrive pre-sorted.

It leaves traces.

Files. Manifests. Syntax. Relations. State. Events. Data. Representation.

OX-DX begins with what can be observed, preserves provenance, names what the evidence supports, and uses a graph when one tree would lie about the relationships.

The project carries ancient questions into modern systems work: what is a thing, what relates it to another thing, what changed, what was observed, what is only representation, and what remains unknown?

The answer is not mysticism disguised as software.

The answer is disciplined engineering with room for reflection.

**EVIDENCE FIRST.**

Extended narrative: `communication/brand-story.md`.

Editorial expression: `brand-manifesto.md`.

## 18. Texture

Canonical principle:

**CLEAN STRUCTURE. DIRTY SURFACE.**

Dirty means controlled friction.

Approved logic:
- trace erosion;
- scan break;
- signal loss;
- compression scar;
- fragmentation / boundary wear.

Reject:
- random dirt;
- random VHS;
- random film grain;
- generic distressed paper;
- arbitrary scratches.

Damage affects persistence.

It does not corrupt construction logic, text, diagrams, or master-logo clarity.

## 22. Motion

Axiom:

**MOTION IS RESOLUTION.**

Operational rule:

**RESOLVE, DON'T DECORATE.**

Canonical visual operation:

`FIELD → RIFT → TRACE → PULSE → GRAIN`

Motion may reveal:
- observation;
- relation;
- trace;
- persistence;
- resolution;
- state transition.

At least one invariant should remain fixed.

Support `prefers-reduced-motion`.

Avoid generic slide/fade as the identity language, ambient particles, decorative glitch loops, and fake progress.

## 24. Brand Applications

| Surface | Logo use | Copy style | Visual density | Allowed | Forbidden |
|---|---|---|---|---|---|
| README | Full lockup/header or symbol | Clear + deep | Medium | dividers, diagrams, limited supporting grammar | decorative overload, stale technical claims |
| GitHub | Logo/avatar + restrained banner | Operational | Low–medium | canonical phrases, release graphics | hype, marketing-only status |

| Documentation | Symbol/wordmark restrained | Technical | Low | diagrams, evidence notation | texture over critical content |
| CLI | Usually text identity; logo optional in docs only | Factual | Minimal | exact status/terms | marketing copy in machine output |
| Release | Mark + explicit version/status | Factual/confident | Medium | deterministic surface friction | implying roadmap completion |
| Social | Mark/lockup | Sharp, concise | Medium | one canonical idea | unsupported absolute claims |
| Presentation | Mark + section system | Progressive disclosure | Medium | diagrams, visual grammar, strong voids | dense decorative dashboards |
| Merchandise | Master mark or canonical phrase | Minimal | Low | monochrome/high-contrast identity | sacred text decoration, illegible grunge, fake technical notation |

Website/UI work must derive from this system; Brand Bible v1.0 does not itself build a website.
