# OX-DX Canonical Terminology — Brand Bible v1.0

This is the canonical communication terminology source for OX-DX Brand Bible v1.0.

Normative technical sources still win on ontology/schema/engine semantics.

| Term | Canonical definition | Approved short form | Incorrect / avoid | Context |
|---|---|---|---|---|
| **OX-DX** | Umbrella public brand and system identity. | OX-DX | OX Engine, DX Engine, generic “AI platform” | Brand, website, GitHub, public ecosystem. |
| **Universal Ontology** | Normative 49-type vocabulary, v1.0.0, organized as 7 zones × 7 levels and used as a resolution spine over a graph. | ontology / canonical vocabulary when unambiguous | 49-folder hierarchy, universal filesystem, religious doctrine | Specification and technical explanation. |
| **Universal Ontology & Experience Engine** | Public conceptual system/product descriptor for OX-DX. | product/system descriptor | Universal Experience Engine, Ontology Experience Engine | Brand/product explanation. |
| **Universal Ontology Engine** | Current Rust technical engine implementing the ontology/graph/evidence contracts. | engine / Rust engine | OX-DX as a synonym for a crate; DX Engine | Technical implementation. |
| **Resolution** | Movement across increasingly specific conceptual or representational scales while preserving relevant distinctions and provenance. | resolution | reduction, forced drill-down, “ultimate truth” | Ontology, representation, visual language. |
| **Resolution Spine** | Stable ordered sequence of the 49 canonical types; resources may skip unmaterialized levels. | spine | mandatory hierarchy, 49 physical containers | Ontology architecture. |
| **Evidence** | Observable information that can support a claim, classification, relation, or projection. | evidence | truth, proof of everything | Engineering and communication. |
| **Native Evidence** | Evidence exposed by a source system in its own structure, syntax, manifests, names, locations, runtime, or representation forms. | native evidence | canonical replacement structure | Discovery and adapters. |
| **Observation** | Recorded finding based on available evidence. | observation | ownership, containment | Discovery, syntax, runtime. |

| **Provenance** | Information describing where, when, or from what source evidence was obtained. | trace/source context | identity | Source spans, revisions, adapters. |
| **Identity** | Stable semantic identifier for a resource, not solely derived from source position/path when a stable semantic identifier can be established. | stable identity | line number, source span alone | Graph/node identity. |

| **Typed Graph** | Graph with canonical node types and defined edge kinds/invariants. | typed graph | generic network | Engine architecture. |
| **Projection** | Explicit justified view of a resource at another ontology level without replacing the source resource. | projection | rewrite, mutation | Semantic/dynamic/representation mapping. |

| **Representation** | Concrete encoded/realized form connected explicitly to a resource or value. | representation | meaning itself | DATA/TOKEN/CHARACTER/BIT boundaries. |

| **Structure** | Observable or modeled organization and structural ownership of resources. | structure | every graph relation | Repository/source/component ownership. |
| **Experience** | Brand-level horizon where structured evidence and behavior become interpretable/useful to people or systems. | experience horizon | implemented ontology level, completed subsystem | Product/brand narrative. |
| **TYPE** | One of the 49 canonical ontology levels. | TYPE | native specialization | Ontology classification. |

| **CONTAINS** | Structural ownership edge consistent with parent. | containment | reference/projection/observation | Structural graph. |
| **PROJECTS_TO** | Explicit edge to another justified ontology-level view. | projection edge | source mutation | Projection graph. |
| **REPRESENTED_AS** | Edge connecting a resource/value to a concrete representation. | representation edge | containment | Representation graph. |
| **OBSERVED_AT** | Edge linking an observation/execution to a target/location where it was observed. | observation edge | ownership/containment | Dynamic observation. |

## Technical edge vocabulary

When exact semantics matter, use the implementation's registered edge names:

`CONTAINS · REFERENCES · SPECIALIZES · DEPENDS_ON · INVOKES · PRODUCES · CONSUMES · CAUSES · PROJECTS_TO · REPRESENTED_AS · OBSERVED_AT`

Do not invent decorative relation names in engineering claims.

## Version terminology

Keep separate:
- **OX-DX Brand Bible v1.0** — brand-system version;
- **Universal Ontology v1.0.0** — normative ontology version;
- **Universal Ontology Engine v0.x** — software release train;
- schema version/identifier — governed by the schema contract.

Never infer one from another.
