# OX-DX Canonical Visual Identity

This file consolidates visual authority. Detailed construction remains in `../visual/`.

### MASTER

- Logo: `assets/brand/logo/ox-dx-logo-primary.svg`
- Icon / primary symbol: `assets/brand/icon/ox-dx-icon.svg`
- Wordmark: `assets/brand/wordmark/ox-dx-wordmark.svg`

### CANONICAL LOCKUPS

- `assets/brand/lockups/ox-dx-lockup-horizontal.svg`
- `assets/brand/lockups/ox-dx-lockup-stacked.svg`

### DERIVED / VARIANT

Black, white, dark, light, inverse, monochrome, PNG, WEBP, favicon, and crop exports are derived assets. They may adapt color/background/format but must not silently alter master geometry.

### DEPRECATED

Legacy supporting compositions may remain in the repository for history or migration. They are not a second canonical visual system.

The master logo must never be recreated from screenshots.

**SVG is canonical. Raster is derived.**

## Supporting visual language

Canonical system:

**Interrupted Evidence Field**

Canonical concept:

**A visual notation system discovered inside a computational artifact.**

Core construction:
- Interrupted Dyad;
- diamond/cut-square witness anchor;
- measured break;
- persistence rail;
- provenance tail;
- void slot;
- deterministic disturbance.

Graphic vocabulary:

`LINE · NODE · FRAME · LAYER · VOID · BREAK · TRACE · SIGNAL · DENSITY · FIELD · EDGE · ANCHOR`

These are visual constructs only. They are not ontology levels, TYPEs, KINDs, graph edge kinds, or engine phases.

## Geometry

Canonical specialist source:

`assets/documentation/visual/geometry-system.md`

Rules:
- controlled asymmetry;
- open/interrupted frames;
- functional 45° cuts;
- partial continuity;
- variable density;
- resolution-dependent transformation;
- no default circle as supporting node;
- no generic hexagon/circuit-board/isometric grammar.

The circular observation field inside the approved master mark is a logo-specific canonical geometry and is not a rule that every supporting node must be circular.

## Typography

Canonical source:

`assets/documentation/technical/typography.md`

- Brand wordmark: canonical vector geometry only.
- Headline: system-accessible sans, strong weight, compact line height.
- Body: readable system sans.
- Technical/mono: system monospace.
- Technical labels: compact uppercase mono when appropriate.

Long-form technical text never uses decorative display typography.

Typography should feel editorial, technical, hard-edged, and readable—not generically brutalist.

`assets/vector/original/patterns/`

Legacy `assets/vector/patterns/` patterns are retained only for historical/migration use after Brand Bible v1.0.

## Texture

Canonical principle:

**CLEAN STRUCTURE. DIRTY SURFACE.**

“Dirty” describes controlled friction, not random dirt.

Approved texture logic:
- trace erosion;
- signal loss;
- scan break;
- compression scar;
- boundary wear / fragmentation.

Canonical new-work textures:

`assets/vector/original/textures/`

Reject random VHS, random film grain, paper distress, generic scratches, or noise that carries no meaning.

## Negative space

Canonical source:

`visual/negative-space.md`

A **Void Slot** can represent unknown, distance, scope, boundary, pause, or resolution gap.

OX-DX should visibly refuse to fill space that evidence does not justify.

## Iconography

Canonical source:

`visual/iconography.md`

OX-DX-native icons derive from hard-edged master geometry and preserve meaningful voids.

Universal actions such as search, close, download, or accessibility may use established conventional symbols when clearer.

## Motion

Axiom:

**MOTION IS RESOLUTION.**

Operational rule:

**RESOLVE, DON'T DECORATE.**

Canonical timing:
- 98 ms micro;
- 196 ms witness;
- 294 ms resolve;
- 490 ms field.

Canonical visual transformation:

`FIELD → RIFT → TRACE → PULSE → GRAIN`

Motion must preserve an invariant and support `prefers-reduced-motion`.

## Interaction

Canonical principle:

**INTERACTION = EXAMINING EVIDENCE**

Prefer inspect, trace, resolve, observe.

Avoid gamification and decorative response.

## Accessibility

Required for every application:
- sufficient text/foreground contrast;
- meaning must survive monochrome;
- no critical state communicated by color alone;
- readable type sizes and line lengths;
- diagrams remain understandable without hover/motion;
- focus remains visible;
- reduced-motion path exists;
- texture never damages critical text;
- compact responsive layouts remove context before shrinking critical geometry.

Accessibility is not an optional aesthetic variant. It is part of brand correctness.
