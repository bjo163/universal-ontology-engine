# OX-DX Bad → Good Examples

These transformations demonstrate the communication system. “Bad” lines are intentionally included as examples to reject.

## 1 — Generic hype

**BAD:** “OX-DX is a revolutionary AI-powered universal intelligence platform.”

**GOOD:** “OX-DX provides a universal resolution vocabulary and typed graph for heterogeneous evidence.”

## 2 — Absolute truth

**BAD:** “OX-DX discovers the truth.”

**GOOD:** “OX-DX preserves evidence and makes classification, relation, and projection explicit.”

## 3 — Forced hierarchy

**BAD:** “The 49-level hierarchy forces every system into a universal structure.”

**GOOD:** “The 49 levels form a resolution spine over a graph; native structures remain authoritative.”

## 4 — Runtime ownership

**BAD:** “Runtime executions belong under their source element.”

**GOOD:** “Runtime execution is an observation; when associated with a target, the relationship is explicit through `OBSERVED_AT`.”

## 5 — Provenance as identity

**BAD:** “The line number is the node identity.”

**GOOD:** “The source span records provenance; stable identity must not rely on line numbers alone when a semantic identifier can be established.”

## 6 — TYPE and KIND

**BAD:** “`rust-function` should become a new ontology level.”

**GOOD:** “A Rust function is native evidence or specialization; `KIND` does not create a new canonical `TYPE`.”

## 7 — Filename inference

**BAD:** “Anything in a `services/` folder is definitely a SYSTEM.”

**GOOD:** “A directory name is evidence, not sufficient proof of canonical semantic identity.”

## 8 — Compiler claim

**BAD:** “OX-DX compiles and fully understands seven languages.”

**GOOD:** “Rust uses AST observation through `syn`; six additional languages currently provide deterministic syntax observation, not compiler-grade semantic analysis.”

## 9 — Representation

**BAD:** “Everything is ultimately just bits, so higher levels do not matter.”

**GOOD:** “BIT marks a representation boundary; finer representation does not erase higher-level identity, context, or meaning.”

## 10 — Projection

**BAD:** “Projection converts the native resource into the canonical type.”

**GOOD:** “Projection adds an explicit justified view while preserving the originating native evidence.”

## 11 — Graph

**BAD:** “Every graph edge is a parent-child relation.”

**GOOD:** “Containment is one edge class; references, projection, representation, causation, and observation remain distinct.”

## 12 — Current runtime capability

**BAD:** “OX-DX already observes every runtime event.”

**GOOD:** “Runtime observation is a planned phase; the current model already defines the distinction between execution observations and structural ownership.”

## 13 — Experience

**BAD:** “The Experience Engine is fully implemented.”

**GOOD:** “Experience is the brand-level horizon; current implementation status is stated separately and later capabilities remain gated or planned.”

## 14 — Quranic authority

**BAD:** “The 49 levels are technically correct because the Qur'an specifies them.”

**GOOD:** “Quranic inspiration is philosophical; the 49-level ontology is independently specified, testable, and reviewable.”

## 15 — Universal completion

**BAD:** “OX-DX is fully universal and handles every system.”

**GOOD:** “OX-DX defines a universal ontology vocabulary; implemented adapters and discovery capabilities have explicit current scopes.”

## 16 — Read-only discovery

**BAD:** “Discovery reorganizes repositories into the ontology.”

**GOOD:** “Discovery is read-only; it observes native structure and records justified canonical classifications without renaming the target.”

## 17 — Verification

**BAD:** “CI proves the architecture is perfect.”

**GOOD:** “CI verifies named invariants and tests at their defined scope; it does not establish claims outside those checks.”

## 18 — Missing evidence

**BAD:** “No node was found, so the concept does not exist.”

**GOOD:** “No supported evidence for that node was observed in the current input.”
