# OX-DX Foundational Component Specifications

These are future component contracts, not code.

## OX-DX Shell

Purpose: establish global product identity, scope, context, and responsive regions.

Must expose:
- product/surface identity;
- active scope;
- recoverable context;
- focus region.

Must avoid permanent dashboard chrome when context can be represented more directly.

## OX-DX Header

Purpose: orientation and global scope, not KPI display.

Contains only high-value identity, location, context actions, and status required for orientation.

## Context Bar

Purpose: answer **where am I / what am I looking at / what scope is active**.

Should support breadcrumbs only when actual hierarchy exists. Otherwise prefer graph/context labels.

## Resolution Spine

Purpose: expose canonical resolution context and possible deeper inspection without pretending 49 types are a physical folder tree.

Must show gaps/unmaterialized levels honestly.

## Evidence Panel

Purpose: show source/native evidence and classification relationship.

Interpretation must be visually separated from source material.

## Graph Surface

Purpose: expose typed relationships as first-class product structure.

Must inherit Persistence Rail / witness geometry from the visual grammar.

## Inspector

Purpose: reveal focused object attributes, evidence, status, relationships, and provenance.

It is an inspection surface, not a generic CRUD form.

## Provenance Rail

Purpose: keep source/origin visible with low visual dominance.

Must not visually become the object's identity.

## Observation Marker

Purpose: attach observation to a target while preserving separation from structural ownership.

Uses witness geometry + label; color alone is insufficient.

## Status Marker

Purpose: expose state/status label with icon/geometry/text.

No status is represented by color alone.

## Command Surface

Purpose: keyboard-first or text-first inspection/navigation/verification actions.

Future conceptual vocabulary does not rename the current CLI.

## Technical Table

Purpose: dense comparison of technical values/relations with stable columns and keyboard accessibility.

Avoid ornamental row cards.

## Raw Representation Viewer

Purpose: show representation/encoding/raw data with explicit context.

Never imply raw bytes are equivalent to semantic meaning.

## OX-DX information surface

Do not create a generic rounded card and rename it “OX-DX Card.”

An OX-DX information surface should expose:
- object;
- context;
- evidence;
- relation;
- status.

Use edge, frame, density, proximity, label, and intentional void before defaulting to shadow/radius decoration.

## Inspection panel

Panels should use:
- clear hierarchy;
- bounded but often interrupted frame logic;
- controlled density;
- technical labels;
- contextual detail.

Avoid:
- giant empty containers;
- excessive shadows;
- soft floating cards everywhere.
