# OX-DX Data-Dense Interfaces

Priority:

**clarity → traceability → context → density → decoration**

## Tables

Use tables when values align into comparable columns.

Requirements:
- stable headers;
- keyboard access;
- sortable only when sort semantics are clear;
- visible relation/status labels;
- no card-per-row transformation on desktop by default.

## Lists

Use lists for heterogeneous items or relation/event streams.

Expose:
- identity;
- key status;
- relevant source/context;
- relation where meaningful.

## Graphs

Use graphs for relationships that are genuinely graph-shaped.

Provide a list/inspector alternative for precise navigation and accessibility.

## Metadata

Group by meaning:
- identity;
- evidence;
- relation;
- provenance;
- status;
- representation.

Do not create a “metadata” dump simply because information is technical.

## Source spans

Use mono and compact alignment.

Source location stays provenance, not identity.

## Events

Events need:
- time/order if real data exists;
- target;
- event type;
- source/provenance;
- status where supported.

Do not fabricate timeline spacing without real temporal scale.

## Relations

Display exact typed relation names when engineering meaning matters.

## Raw representation

Use fixed-width alignment and explicit offsets/ranges when supplied.

Keep semantic object context reachable.

## Density controls

If user-adjustable density is introduced, it should change spacing/secondary detail—not hide semantic distinctions.
