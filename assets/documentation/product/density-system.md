# OX-DX Density System

OX-DX will inspect technical systems, but not every screen should be dense.

## LOW DENSITY

Use for:
- orientation;
- onboarding/explanation;
- major conceptual transitions;
- broad object context.

Characteristics:
- large voids;
- few relations;
- one primary task;
- minimal metadata.

## MEDIUM DENSITY

Default product working state.

Use for:
- object inspection;
- documentation-like product surfaces;
- selected graph neighborhoods;
- evidence + relation context.

Characteristics:
- primary object + secondary evidence;
- readable metadata;
- controlled rails/panels.

## HIGH DENSITY

Use for:
- technical tables;
- relation lists;
- large metadata sets;
- source events;
- comparison surfaces.

Characteristics:
- compact spacing;
- reduced ornament;
- stronger alignment;
- persistent keyboard navigation.

## INSPECTION DENSITY

A focused mode for deep evidence/provenance/representation work.

Characteristics:
- high information volume;
- raw/source context;
- exact labels;
- reduced brand decoration;
- stable row/column/rail geometry.

## Density transition

Users should be able to move between context and detail.

High density is not a brand virtue by itself.

## Rule

**Expand the interface when the user needs conceptual space. Compress it when the user needs technical comparison.**

Do not make every surface dense merely because the audience is technical.
