# OX-DX Product Originality Review

## Result

**PASS — product rules inherit the established OX-DX visual language instead of defaulting to a dark developer dashboard.**

This is not a claim of global uniqueness.

## Canonical statement

> Designed as an original OX-DX product language with intentional separation from identified common technology-product patterns.

## What makes the product system recognizably OX-DX

- evidence-first hierarchy;
- graph relationships as first-class navigation/inspection;
- Resolution Spine distinct from camera zoom;
- observation visually separate from ownership;
- provenance visible but not identity;
- deliberate unknown/void states;
- open/interrupted inspection surfaces;
- status through text + geometry + restrained color;
- task-dependent density;
- motion as resolution;
- controlled surface friction without “cyberpunk” decoration.

## Patterns explicitly rejected as defaults

- generic Linear/Vercel-style dark productivity shell;
- Raycast/Cursor-like command aesthetic as the whole identity;
- GitHub clone;
- OpenAI/Anthropic chat-first identity;
- Stripe/Supabase dashboard patterns as the default;
- generic IDE chrome;
- left-sidebar + KPI cards;
- glowing cyan node graph;
- circuit-board decoration;
- glassmorphism;
- generic brutalism;
- dark developer dashboard with neon accents.

## Usability boundary

OX-DX may still use familiar:
- tables;
- buttons;
- search;
- tabs where appropriate;
- checkboxes;
- keyboard patterns;
- accessible platform controls.

Originality comes from the relationships among evidence, context, resolution, provenance, and graph—not from making common controls unfamiliar.

## Review test

If the logo and colors are removed, the product should still be recognizable through:
- inspection-first hierarchy;
- witness/focus behavior;
- relation rails;
- deliberate voids;
- evidence/provenance separation;
- resolution behavior.

If not, the implementation is relying on styling rather than the OX-DX product language.
