# OX-DX Product Typography

Source: `../technical/typography.md`.

Do not create a second type system.

## Display / identity

Use the canonical vector wordmark for identity-critical brand use.

Do not recreate OX-DX with a display font.

## Product headline

Use the canonical system sans stack.

Typical role:
- page/task title;
- focused object title;
- major conceptual statement.

Keep headlines concise. Do not turn every inspector section into a hero.

## Section

Use system sans, medium/strong weight, compact line height.

Sections label conceptual regions such as EVIDENCE, RELATIONS, PROVENANCE, REPRESENTATION.

## Body

Readable system sans.

Use normal sentence case and comfortable line length.

## Technical

Use canonical mono stack for:
- commands;
- paths;
- TYPE/KIND names;
- relation names;
- source spans;
- values;
- identifiers;
- provenance.

## Metadata

Use smaller mono or restrained sans.

Metadata stays readable; do not reduce it to decorative microtext.

## Coordinates / ranges

Use mono and tabular alignment where available.

Only show real values.

## Labels

Compact uppercase technical labels are allowed for:
- status;
- section markers;
- relation types;
- small evidence annotations.

## Status

Status labels must remain text-readable in addition to icon/geometry/color.

## Product scale rule

Large space means more context, not merely larger typography.

Compact space should remove secondary labels before critical text becomes unreadable.
