# OX-DX Product UI Philosophy

OX-DX should feel like:

- an instrument;
- a lens;
- an inspection surface;
- a resolution environment.

Not primarily like:

- a business dashboard;
- a generic admin panel;
- a card-management workspace;
- a KPI control center.

## Desired qualities

### QUIET
The interface does not compete with the evidence.

### DENSE WHEN NEEDED
Technical detail can become information-dense during inspection.

### SPACIOUS WHEN THINKING
Conceptual transitions, uncertain boundaries, and cross-context comparison need deliberate voids.

### TECHNICAL
Labels, relations, source context, and status remain explicit.

### EDITORIAL
Hierarchy is composed, not merely boxed.

### RESPONSIVE
More space reveals more context. Less space prioritizes focus.

### PRECISE
Status and relation language do not overclaim.

### SLIGHTLY RAW
Controlled surface friction may communicate trace/erosion but never harm clarity.

## Core metaphor

**THE PRODUCT IS AN INSTRUMENT.**

The interface does not “own” the system under inspection.

It reveals it.

The strongest product experience should feel closer to using an oscilloscope, debugger, graph inspector, or scientific lens than operating a sales dashboard—without copying any of those products visually.

## Interaction rhythm

`OBSERVE → TRACE → RESOLVE`

Observe the current object/evidence.

Trace its origin and relations.

Resolve into more specific context/representation when justified.

The UI may support actions, but action is downstream from understanding.
