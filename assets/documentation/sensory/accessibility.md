# OX-DX Sensory Accessibility

Sensory identity is valid only when meaning survives without each sensory channel.

## Core requirements

- every sound has a visual/text alternative;
- no meaning depends on sound alone;
- no meaning depends on color alone;
- reduced motion is supported;
- silent mode is supported;
- high contrast is supported;
- volume is noncritical;
- critical alerts remain understandable without audio.

## Modes

### FULL SENSORY
Visual + motion + optional sound at intended intensity.

### REDUCED MOTION
- render resolved state directly where possible;
- keep witness, break, status, and relation distinctions;
- minimize temporal transforms;
- audio does not compensate by becoming louder/more frequent.

### SILENT
- remove nonessential audio;
- preserve text, status, geometry, focus, and accessible announcements;
- do not show “sound required” states.

### HIGH CONTRAST
- remove optional texture;
- strengthen key geometry;
- use black/white primary distinction;
- retain labels;
- accent color remains supplementary.

## Flash / photosensitivity

Avoid rapid flashing.

Do not use repeated high-contrast flicker as an error, scan, verify, or transition grammar.

## Vestibular comfort

Avoid:
- large-scale zoom tunnels;
- continuous parallax;
- rapid full-screen displacement;
- long spinning transitions.

## Screen reader

Sensory events that communicate state must expose semantic text/status independent of animation/audio.

## User control

If audio is implemented, provide:
- mute/silent setting;
- separate ambient control where ambient exists;
- respect platform/browser autoplay policies;
- avoid unexpected sound on page load.

## Principle

**ACCESSIBILITY IS NOT A REDUCED BRAND.**

The quiet modes are canonical expressions of OX-DX restraint.
