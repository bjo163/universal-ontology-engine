# OX-DX Sensory Do / Don't

## DO

- Use effects to explain state.
- Use silence.
- Use subtle signals.
- Use related sound families.
- Use resolution as motion.
- Use original deterministic texture.
- Use accessibility alternatives.
- Keep observation non-invasive.
- Let unknown remain quiet.
- Preserve a stable anchor/invariant.
- Make errors local and readable.
- Reduce sensory intensity for repeated events.

## DON'T

- Glitch everything.
- Beep everything.
- Animate everything.
- Use neon for every event.
- Play sounds for every click.
- Use cinematic effects for routine actions.
- Use sound as the only confirmation.
- Use a generic sci-fi scanner line.
- Use confetti/explosion for verification.
- Use red flashing for unknown.
- Use fake progress.
- Distort the master logo.
- Use Quranic text/sacred symbols as sensory decoration.
- Use AI voice/brain/orb aesthetics as the OX-DX identity.

## Decision test

Before adding an effect ask:

1. What happened?
2. What should the user understand?
3. Which channel is the smallest effective carrier?
4. Can silence do the job?
5. Does it survive reduced-motion/silent/high-contrast modes?
6. Is it recognizably OX-DX because of behavior, not because it is “futuristic”?
