# OX-DX Silence System

**SILENCE IS A VALID STATE.**

The system does not need to speak every time the user acts.

## NO SOUND

Default for:
- hover;
- routine navigation;
- passive context changes;
- background observation;
- unknown/unresolved state;
- repeated low-value updates;
- scroll;
- noncritical filter changes.

## NO MOTION

Prefer no motion when:
- state is static;
- repeated motion would become ambient noise;
- reduced-motion mode is active;
- the event is sufficiently communicated by text/geometry;
- background activity does not require attention.

## MINIMAL VISUAL RESPONSE

Use:
- focus witness;
- label update;
- local persistence change;
- small relation trace.

## Unknown

Unknown is usually quiet.

Do not play a warning merely because data is unresolved.

## Repetition suppression

If the same event occurs repeatedly in a short workflow:
- suppress duplicate sound;
- reduce visual intensity;
- keep state text accurate.

Do not create sensory fatigue.

## Background work

Background processes should be silent unless:
- completion needs user attention;
- failure materially affects the user's task;
- the user explicitly opted into audible notification.

## Silent mode

Silent mode removes all non-essential audio.

Critical meaning remains available through:
- text;
- geometry;
- status;
- accessible announcement where appropriate.

Silent mode is first-class, not a fallback.
