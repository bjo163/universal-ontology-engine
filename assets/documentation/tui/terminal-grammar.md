# OX-DX Terminal Grammar

The TUI is the **OX-DX Instrument**.

Core experience:

**SEE → TRACE → RESOLVE**

Secondary:

**OBSERVE → CONNECT → VERIFY**

## Composition law

A recognizably OX-DX TUI surface normally has:
1. one stable focus/selection anchor;
2. one evidence-bearing primary region;
3. one explicit context or resolution indicator;
4. one controlled interruption/open boundary;
5. provenance/observation separated from identity when relevant.

## Monospace

Monospace is the medium, not the identity.

Do not use ASCII art merely because the interface is terminal-based.

## Spatial structure

Meaning comes from:
- position;
- adjacency;
- open boundaries;
- rails;
- indentation only when hierarchy is real;
- whitespace as deliberate context.

## Evidence

Native evidence precedes interpretation.

## Resolution

Current canonical level remains visible/recoverable.

## Controlled imperfection

Use:
- broken separators;
- partial rails;
- asymmetry;
- sparse traces.

Do not use random character noise.

## Quiet state

Nothing happening should look stable.

No ambient spinner.

No blinking decoration.

No status churn.

## Distinction rules

- focus ≠ selected;
- selected ≠ active;
- observed ≠ owned;
- provenance ≠ identity;
- resolution order ≠ containment;
- unknown ≠ error;
- verified ≠ success;
- graph ≠ tree.
