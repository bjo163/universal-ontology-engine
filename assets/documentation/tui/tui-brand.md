# OX-DX TUI Brand Foundation

**Status: CANONICAL TUI SPECIALIST**

Master: `../OX-DX-TUI-SYSTEM-v1.0.md`

## Identity

The OX-DX terminal is:

**AN INSTRUMENT FOR INSPECTING COMPLEX SYSTEMS.**

It is not a dashboard, hacker-movie interface, web-app clone, or generic IDE.

## Brand mark usage

Do not render a huge ASCII logo.

Preferred terminal identity:

`OX-DX`

Optional descriptor beneath it:

`Universal Ontology & Experience Engine`

Use the canonical vector logo only outside terminal text surfaces.

## Terminal wordmark

Canonical textual form:

`OX-DX`

Rules:
- uppercase;
- literal hyphen;
- no ASCII-art expansion;
- no decorative box around the name;
- no random color cycling.

## Prompt identity

Prompt composition must expose:
- instrument identity;
- context/scope;
- current resolution;
- interaction mode/state.

The prompt is structural, not shell cosplay.

Canonical pattern is defined in `prompt-language.md`.

## Banner identity

A banner is rare.

Use only for:
- startup;
- major context reset;
- explicit about/version surface.

Preferred structure:

```text
OX-DX
Universal Ontology & Experience Engine
·· evidence-first inspection
```

Unicode middle dots degrade to ASCII `..` or spaces.

## Status identity

Status is text-first.

Examples:
- `OBSERVED`
- `UNKNOWN`
- `VERIFIED`
- `ERROR`

Only use a status when underlying data supports it.

## Startup identity

Startup rhythm:

`signal → identity → system state → ready`

No fake boot sequence.

No invented hardware checks.

## Shutdown identity

Routine exit should be quiet.

Preferred:

`OX-DX · session closed`

If state was not persisted, say so explicitly when relevant.

No animated shutdown.
