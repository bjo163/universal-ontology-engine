# OX-DX Diagram Language

Architecture diagrams must remain readable in GitHub README rendering and technical documentation.

## Node
Prefer open frame fragment + diamond/cut-square anchor. Plain rectangles are acceptable when dense technical clarity is better.

## Edge
Default to persistence rails. When an exact engine relation matters, label it with canonical names such as `CONTAINS` or `PROJECTS_TO`. Graphic naming never replaces technical edge terminology.

## Boundary
Use open context frames. Closed boundaries are reserved for literal bounded scopes where enclosure is technically meaningful.

## Layers
Use displacement + different interruption positions, not identical translucent cards.

## State
Use boundary cut / anchor shift.

## Flow
Use persistence direction and sequential anchors. Arrowheads are allowed when standard process semantics materially improve comprehension.

## Observation
Add witness bracket and anchor without moving the observed node into the observer.

## Annotation
Micro mono labels may occupy void slots. Never add fake coordinates.

A diagram must work at ~720 px width, in monochrome, without animation, and without hover.
